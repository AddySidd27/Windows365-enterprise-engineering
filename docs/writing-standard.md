# Writing Standard

This repository uses simple professional English.

## Rules

- Use short sentences.
- Use direct verbs: create, assign, check, test, remove, restore.
- Explain one action at a time.
- State what was tested and what was not tested.
- Use the exact Microsoft portal and feature names.
- Use tables only when they make comparison easier.
- Keep theory short. Put the work, result, and evidence first.
- Do not claim production experience from a lab result.
- Do not claim a feature works until it is validated.

## Words to avoid

Avoid filler such as:

- leverage
- robust
- seamless
- comprehensive
- cutting-edge
- best-in-class
- holistic
- powerful solution
- in today's digital landscape
- this repository demonstrates a deep understanding

## Preferred wording

Instead of:

> This comprehensive solution leverages Microsoft Intune to provide robust endpoint management.

Write:

> I used Microsoft Intune to apply policy, deploy apps, check compliance, and review device status.

Instead of:

> This use case showcases seamless Cloud PC lifecycle management.

Write:

> I tested Restart, Resize, Move, Restore, and Reprovision as separate operations because each action has a different user and data impact.

## Evidence wording

Use:

> The Intune report showed the pilot Cloud PC as Compliant. Company Portal also showed that the device could access company resources.

Do not use:

> The screenshot proves an enterprise-grade security posture.
